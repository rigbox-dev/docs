This guide walks you through creating a workspace, starting it, reconciling template apps, and validating live routing.

## Prerequisites

- A Rigbox account ([sign up here](https://rigbox.dev/signup))
- The Rigbox CLI installed: `curl -fsSL https://rigbox.dev/install.sh | bash`

## Step 0: Authenticate

The CLI opens your browser to sign in and stores credentials locally, so the rest of these commands need no tokens or headers.

```bash
rig login
```

## Step 1: Deploy an OpenClaw Workspace

`rig template deploy` creates a workspace with template defaults. For OpenClaw, this provisions an `openclaw` image workspace. Replace `<WORKSPACE_NAME>` with a name of your choice (this walkthrough uses `my-bot`).

```bash
rig template deploy --template openclaw --name my-bot
```

Example output:

```json
{
  "workspace": {
    "id": "ws-a1b2c3d4",
    "name": "my-bot",
    "image": "openclaw",
    "status": "provisioned",
    "ram_mb": 4096,
    "disk_size_mb": 10240,
    "vcpu_count": 2,
    "created_at": "2025-01-15T10:30:00Z",
    "updated_at": "2025-01-15T10:30:00Z"
  },
  "message": "Workspace 'my-bot' created from template 'OpenClaw Bot'. Start it to begin working.",
  "installed_apps": [],
  "expected_apps": []
}
```

## Step 2: Start the Workspace

Start the workspace by name. Add `--wait-for-apps` to block until its apps come up, so you can skip the manual wait below.

```bash
rig workspace start --workspace my-bot
```

## Step 3: Wait Until Running

Check the workspace's status until it reports `running`:

```bash
rig workspace ls
```

The workspace takes a few seconds to boot. Re-run the command until `my-bot` shows `running`, or start it with `--wait-for-apps` to block automatically.

## Step 4: Reconcile Template Apps

Ensure expected template apps (for example the OpenClaw gateway) exist:

```bash
rig workspace reconcile --workspace my-bot
```

## Step 5: List Apps and Validate Live Health

List apps:

```bash
rig app ls --workspace my-bot
```

Check a specific app is reachable before surfacing its URL in your own UI:

```bash
rig app health --app <APP_NAME>
```

Expected output:

```json
{
  "live": true,
  "service_status": "running",
  "port_open": true
}
```

## Optional: Configure AI Settings

For workspaces with AI integration, set the AI mode:

```bash
rig workspace ai mode --workspace my-bot managed
```

To also pin a provider and model, use the typed config endpoint via `rig api`:

```bash
rig api PUT /v1/workspaces/<WORKSPACE_ID>/ai-config --body - <<'JSON'
{
  "mode": "managed",
  "provider": "google",
  "model": "google/gemini-2.5-pro"
}
JSON
```

Use `null` on nullable fields (for example `api_key`) to explicitly clear values. Omitted fields keep their existing values.
