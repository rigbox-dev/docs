The managed AI proxy lets your workspace code call supported AI providers without putting provider API keys in the VM. Rigbox holds managed provider keys on your behalf, injects them at request time, and tracks usage against your credit balance.

<Warning>
The financial rules on this page describe upcoming **paid-v1**, pending rollout. New paid plans include no AI credits. See [pricing and billing](/concepts/pricing-and-billing) and the [managed wallet](/ai/managed-wallet) for purchases, holds, legacy balances, and verified renewals. Check your account's current Billing state before relying on rollout-specific behavior.
</Warning>

## Before you begin

Use the [v0.13 CLI](/guides/install-cli) and [authenticate](/cli-reference/authentication). Run workspace-management and recipe commands from your local terminal. Commands identified as running inside a workspace require its console terminal or SSH session. Replace example resource IDs with the values returned for your account.

Start the target workspace first and verify its identity with `rig workspace ls`. AI calls require managed credits or an appropriately configured provider account.

## How It Works

Every workspace can reach the proxy at `http://172.16.0.1:9090` from inside the VM. When managed mode is active, SDK requests configured to use this endpoint pass through that bridge-local proxy, which fronts an OpenRouter gateway. The proxy:

1. Receives the request addressed to the proxy by your workspace code
2. Resolves the workspace from the VM's source IP on the compute bridge
3. Injects Rigbox's managed OpenRouter key (your VM never sees it)
4. Forwards the request to OpenRouter, which routes to the appropriate upstream provider for the requested model
5. Reserves estimated funds before forwarding and settles confirmed usage in the account wallet
6. Returns the response to your code

OpenRouter acts as a single gateway in front of every supported model family, so you only point your SDK at one endpoint regardless of which provider's model you ask for. Pick the upstream provider by choosing the model slug (e.g.&nbsp;`anthropic/claude-sonnet-4`, `openai/gpt-4o`, `google/gemini-2.5-pro`).

<Tip>
Managed workspaces inject `OPENROUTER_BASE_URL=http://172.16.0.1:9090/v1` and `OPENROUTER_API_KEY` at workspace boot, so SDKs and CLI tools that read OpenRouter env vars work out of the box. For tools that read the OpenAI variables instead, `rig proxy on` prints the matching `export` statements for your shell, scripts, or CI.
</Tip>

## Endpoints

The proxy speaks two HTTP shapes — OpenAI-compatible (used by most SDKs and tools) and an Anthropic-shaped passthrough for Claude Code. Both terminate on the same OpenRouter gateway behind the scenes.

| Endpoint | Shape | Notes |
|----------|-------|-------|
| `http://172.16.0.1:9090/v1/chat/completions` | OpenAI | Default route for everything OpenAI-compatible. Pick the upstream model with the `model` field (`anthropic/...`, `openai/...`, `google/...`, etc.). |
| `http://172.16.0.1:9090/v1/embeddings` | OpenAI | Embedding models. |
| `http://172.16.0.1:9090/v1/models` | OpenAI | List models available to your account. |
| `http://172.16.0.1:9090/v1/messages` | Anthropic | Native Anthropic Messages-API passthrough used by Claude Code. Anthropic clients reach it with the proxy root as their base URL. Paid-v1 streams reserve funds and settle confirmed completed usage; interrupted or uncertain usage retains a durable hold for reconciliation. |
| `http://172.16.0.1:9090/rig/v1/usage` | Rigbox | Per-subject AI spend over a rolling window. See [Per-subject cost and budgets](#per-subject-cost-and-budgets). |
| `http://172.16.0.1:9090/brave` | Brave Search | Web Search API when configured for your environment. |

<Tip>
OpenAI-shape responses now carry the settled rigbox-credit cost of each call (`X-Rigbox-Cost-*` headers + `usage.cost_micro`/`cost_credits`), and multi-tenant apps can attribute, read, and cap cost per end-user. See [Per-subject cost and budgets](#per-subject-cost-and-budgets).
</Tip>

<Note>
A configured `free` alias is a model route, not an account free trial or promise of zero cost. Zero-credit settlement requires provider-confirmed zero usage. Missing cost metadata or a model name alone does not establish a free request.
</Note>

## Base URLs for clients

Clients take a base URL and add the endpoint path themselves, so the base URL depends on the API shape:

| Client | Base URL variable | Value | The client adds |
|--------|-------------------|-------|-----------------|
| OpenAI-compatible SDKs and tools | `OPENAI_BASE_URL` (or `OPENROUTER_BASE_URL`) | `http://172.16.0.1:9090/v1` | `/chat/completions`, `/embeddings`, … |
| Anthropic SDKs and Claude Code | `ANTHROPIC_BASE_URL` | `http://172.16.0.1:9090` | `/v1/messages` |

Don't add `/v1` to an Anthropic base URL: the client would request `/v1/v1/messages`. The [Claude Code catalog item](/guides/ai-coding-tools#claude-code) sets `ANTHROPIC_BASE_URL` to the proxy root for you.

## Credit Tiers

Use `rig status`, your account's credit response, and Billing to inspect available funds, held funds, and balance. Starter, Developer, and Pro include no AI grant. An active paid subscriber may buy $13 / 1,000 credits separately, representing approximately $10 of upstream usage and a 30% service markup. BYOK remains available with provider billing.

One credit represents approximately $0.01 of upstream usage; the pack's markup is not added again at settlement. Existing funds are preserved as a non-expiring opening grant. Legacy Pro Managed receives 2,000 credits per uniquely verified paid period, with no recurring 250-credit free grant or calendar reset. See [the wallet contract](/ai/managed-wallet).

## Activate Managed Mode

### With the CLI

Set a workspace to managed mode with `rig workspace ai mode`:

```bash
rig workspace ai mode --workspace <workspace_id> managed
```

The command suggests the environment for agents that don't read the OpenRouter variables, with each client's base URL:

```text
✓ my-project → managed

  Point your agent's provider env at the proxy (Rigbox credits). Suggested:
    rig workspace env set OPENAI_BASE_URL=http://172.16.0.1:9090/v1 OPENAI_API_KEY=managed-by-rigbox -w my-project
    rig workspace env set ANTHROPIC_BASE_URL=http://172.16.0.1:9090 ANTHROPIC_API_KEY=managed-by-rigbox -w my-project

  OpenAI-compatible clients take the /v1 base; Anthropic clients add /v1/messages themselves.
  The proxy intercepts and injects your real upstream key.

  If you turn the proxy off inside the workspace (rigbox proxy off), calls fail until you turn it
  back on or switch to byok with a real key.
```

Run inside the workspace, `rig workspace ai mode managed` changes that workspace and prints the same suggestions without `-w`.

Provider and model are account-level defaults. `rig ai defaults` with no flags shows them; pass flags to change them:

```bash
rig ai defaults
rig ai defaults --provider google --model google/gemini-2.5-pro
```

Inside a workspace, `rig ai defaults` shows the defaults but can't change them; change them from your machine.

### Inside a Workspace VM

Managed workspaces already inject `OPENROUTER_BASE_URL` and `OPENROUTER_API_KEY` into every login shell, so most tools work without any setup step. The `rig proxy on` helper is a convenience for scripts or CI where you want the exports printed explicitly:

```bash
eval "$(rig proxy on)"
```

It prints `export` statements for the proxy's root and its OpenAI-compatible `/v1` base, with the `managed-by-rigbox` placeholder key that the proxy replaces:

```text
export OPENAI_API_KEY='managed-by-rigbox';
export OPENAI_BASE_URL='http://172.16.0.1:9090/v1';
export RIGBOX_AI_PROXY_URL='http://172.16.0.1:9090';
```

Tools that read those variables use the proxy; explicit SDK settings may override them. For Anthropic clients, set `ANTHROPIC_BASE_URL` to the proxy root as described in [Base URLs for clients](#base-urls-for-clients).

<Tip>
Use `rig proxy status` to see the configured endpoints, current shell state, and credit balance.
</Tip>

To deactivate:

```bash
eval "$(rig proxy off)"
```

`rig proxy off` unsets `RIGBOX_AI_PROXY_URL`, and unsets a provider variable only while it still points at the proxy: a base URL such as `OPENAI_BASE_URL` or `ANTHROPIC_BASE_URL` whose value is the proxy address, or a key such as `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` that holds the `managed-by-rigbox` placeholder. Your own keys and base URLs stay set, and so do the workspace's `OPENROUTER_BASE_URL` and `OPENROUTER_API_KEY`.

## Per-subject cost and budgets

If your app fronts many end-users through a single workspace — a multi-tenant SaaS, an agent platform, a shared chatbot — you can attribute managed-AI cost to each end-user ("subject"), read their spend, and cap it. The proxy is the **mechanism** (accurate cost, attribution, enforcement); your app owns the **policy** (which tiers exist, the amounts, the windows) and asserts the subject id over the already-IP-attested channel.

This covers the OpenAI-shape endpoints (`/v1/chat/completions`, `/v1/completions`, `/v1/responses`, `/v1/embeddings`).

### Read the settled cost of a call

The settled rigbox-credit cost rides on the response — no second lookup. **1 credit ≈ $0.01; 1,000,000 microcredits = 1 credit.** `cost_micro` is the exact integer; `cost_credits` is the convenience float. The fields are best-effort: present only when the upstream model reports a cost, so **don't treat their absence as zero.**

<CodeGroup>
```bash Buffered
curl -i "$OPENROUTER_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-4o-mini","max_tokens":16,
       "messages":[{"role":"user","content":"hi"}]}'
```

```http Response headers + body
X-Rigbox-Cost-Micro: 360
X-Rigbox-Cost-Credits: 0.000360

{"usage":{"prompt_tokens":12,"completion_tokens":3,"cost":3.6e-06,
          "cost_micro":360,"cost_credits":0.00036}}
```
</CodeGroup>

For streaming (`"stream": true`), the same `cost_micro` / `cost_credits` are spliced into the final `usage` chunk:

```
data: {"usage":{"completion_tokens":2,"cost_micro":300,"cost_credits":0.0003}}
data: [DONE]
```

### Attribute a call to a subject

Tag any call with `X-Rigbox-Subject` (it wins) or the OpenAI `user` body field. Trimmed; empty = unattributed; capped at 256 characters.

```bash
curl "$OPENROUTER_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "X-Rigbox-Subject: tenant-42" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-4o-mini","messages":[{"role":"user","content":"hi"}]}'
```

### Read a subject's rolling spend

```bash
curl "http://172.16.0.1:9090/rig/v1/usage?subject=tenant-42&window=24h"
```
```json
{"subject":"tenant-42","window_seconds":86400,
 "credits":0.00072,"credits_micro":720,
 "input_tokens":8,"output_tokens":10,"requests":1}
```

`window` accepts `30s` / `15m` / `5h` / `7d` or a bare number of seconds (default `86400`). It's a rolling window scoped to your workspace — you can only read your own subjects, and they're isolated from each other. Attribution is forward-only. This read alone is enough to enforce policy yourself (read spend → decide whether to call); the next section is for letting the proxy do it. See the [Get Subject Usage API reference](/api-reference/managed-proxy/get-subject-usage).

### Enforce budgets and rate limits

Declare the policy inline on each request and the proxy checks it against the subject's recorded spend **before** the call runs:

```bash
curl "$OPENROUTER_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "X-Rigbox-Subject: tenant-42" \
  -H "X-Rigbox-Subject-Budget: 50;period=30d" \
  -H "X-Rigbox-Subject-Rate: 5;window=1h" \
  -H "X-Rigbox-Subject-Rate: 100req;window=1m" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-4o-mini","messages":[{"role":"user","content":"hi"}]}'
```

| Header | Cardinality | Meaning |
|--------|-------------|---------|
| `X-Rigbox-Subject-Budget` | at most one | Total spend cap: `<amount>;period=<window>` |
| `X-Rigbox-Subject-Rate` | repeatable | Sliding limit: `<amount>;window=<window>` |

- **Amount** — a bare number is credits (`5` = 5 credits); a `req` suffix is a request count (`100req`).
- **Window** — `5h` / `30m` / `3600` / `7d`.
- Enforcement requires `X-Rigbox-Subject`; with no subject, the limit headers are ignored.

On breach the call is rejected before any spend, with a `Retry-After` header and a structured body. OpenAI SDKs still read `error.message` / `error.code`; `error.details` is the rich payload for your UX:

<CodeGroup>
```json 429 subject_rate_limited
{"error":{
  "code":"subject_rate_limited",
  "message":"Subject 'tenant-42' hit a rate limit: 5 credits per 3600s.",
  "details":{
    "reason":"subject_rate_limited","subject":"tenant-42",
    "limit":{"kind":"credits","amount":5.0,"window_seconds":3600},
    "used":{"credits":5.0,"credits_micro":5000000},
    "resets_at":"2026-06-15T13:00:00Z","retry_after":3600}}}
```

```json 402 subject_over_budget
{"error":{
  "code":"subject_over_budget",
  "message":"Subject 'tenant-42' is over its budget: 50 credits per 2592000s.",
  "details":{
    "reason":"subject_over_budget","subject":"tenant-42",
    "limit":{"kind":"credits","amount":50.0,"window_seconds":2592000},
    "used":{"credits":50.3,"credits_micro":50300000},
    "resets_at":"2026-07-15T06:04:15Z","retry_after":2592000}}}
```
</CodeGroup>

A budget breach returns **402 `subject_over_budget`**, a rate breach **429 `subject_rate_limited`** (budget is evaluated first if several trip), and a malformed limit header **400 `subject_limit_malformed`**. The full schema is in the [Chat Completion API reference](/api-reference/managed-proxy/chat-completions).

<Warning>
Per-subject budgets are **advisory app policy**, not a hard wall. Concurrent calls can overshoot a subject budget because in-flight charges have not settled yet. Account-wallet reservations are serialized before forwarding, but estimates are not a guarantee of final cost: underestimated confirmed usage is retained as debt. `resets_at` / `retry_after` describe the subject's rolling window, not wallet renewal. Because your app asserts the subject ID and limits, this guards against ordinary tenant over-spend, not a compromised app process.
</Warning>

<Note>
`/v1/messages` (Anthropic) and the audio endpoints are not yet covered by per-subject attribution or enforcement.
</Note>

## What Happens When Credits Run Out

When available funds cannot cover a new managed request's reservation:

1. **API requests return HTTP 402** - the proxy rejects new managed AI calls until credits are available
2. **Billing offers separate credit purchases** while your paid plan is active, or you can deliberately configure [BYOK](/guides/byok). Upgrading a new compute plan does not include AI credits.
3. **Wallet exhaustion alone does not stop non-AI services**. Separate compute entitlement, policy, and resource limits still apply.

<Warning>
If you have a long-running agent or automated pipeline, it will start receiving 402 errors once credits are exhausted. Consider monitoring your balance programmatically using the credits endpoint.
</Warning>

## End-to-End Example

Here is a complete flow: activate managed mode, make an AI call from inside the workspace, then check remaining credits.

**Step 1 - Activate managed mode for a workspace:**

```bash
rig workspace ai mode --workspace ws_abc123 managed
rig ai defaults --provider google --model google/gemini-2.5-flash-lite
```

**Step 2 - Inside the workspace VM, configure the shell and make a call:**

```bash
# (Optional — managed workspaces export these at login already.)
eval "$(rig proxy on)"

curl -sS "$OPENROUTER_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemini-2.5-flash-lite",
    "messages": [
      {"role": "user", "content": "Explain microVMs in one paragraph."}
    ]
  }' | jq .
```

**Step 3 - Check remaining credits:**

`rig status` prints your balance directly. For the raw payload, query the endpoint with `rig api`:

```bash
rig api GET /v1/users/me/credits
# {"remaining": 1795, "total": 2000, "mode": "managed"}
```

<Note>
Reservation happens before forwarding. Financial settlement can complete after the response, and uncertain or interrupted requests keep a durable hold. Refresh the wallet for confirmed financial state; a received response is not proof that all holds are finalized.
</Note>

## Switching Providers and Models

Because the managed gateway is OpenRouter, you can switch the upstream provider and model at any time by changing the `model` field on your request — there's no environment change, no proxy restart, and no separate "configure provider" step:

```bash
# Same endpoint, different upstream model
curl -sS "$OPENROUTER_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "openai/gpt-4o", "messages": [{"role": "user", "content": "hi"}]}'
```

The account-level AI defaults (set with `rig ai defaults`) define the default provider and model used by tools that don't ask for one explicitly, and are also surfaced by `rig proxy status`.

## Verify and troubleshoot

Inside the workspace, inspect `rig proxy status`, then make one small request with your chosen tool. Verify the configured endpoint and check the corresponding Rigbox or provider usage. After changing keys or mode, start a fresh shell and restart processes that retained their old configuration. Never print a provider key to verify it.

For failures, start with [runtime logs](/operate/app-logs), [health checks](/operate/health), or [resource exhaustion](/operate/resources).
